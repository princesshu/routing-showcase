# TanStack Start

The TanStack Start part of [Routing Showcase](..): a small, runnable reference for file-based routing in TanStack Start, where TanStack Router does all of the routing. Every pattern below has a working route in [`src/routes/`](src/routes) and a short explanation in [`docs/`](docs).

Built with TanStack Start on Vite, React and strict TypeScript. Exact versions are pinned in [`package.json`](package.json); CI runs on the Node.js version set in [`.github/workflows/ci.yml`](../.github/workflows/ci.yml).

## Getting started

```bash
pnpm install   # once, at the repository root
cd tanstack-start
pnpm dev
```

Open http://localhost:3001 (port 3000 belongs to the Next.js app). The home page links to every pattern.

CI runs the same checks you can run locally in `tanstack-start/`:

```bash
pnpm lint
pnpm typecheck           # tsc --noEmit, against the committed route tree
pnpm build               # also regenerates src/routeTree.gen.ts
pnpm route-map --check   # README route map matches the build
```

CI also fails if the build changed `src/routeTree.gen.ts`, so the committed route tree always matches `src/routes/`. Formatting is checked once for the whole repository, with `pnpm format:check` at the root.

Rendering, as set by each route's `ssr` option: **SSR** renders on the server for the first request, **data-only** runs the loader on the server and renders in the browser, **client only** leaves the route to the browser. **Prerendered** pages are also written to `dist/client` as HTML at build time. **On request** is a server route. `/internal/team` is served at `/team` by the [rewrite](docs/redirects-and-rewrites.md#rewrites) in `src/router.tsx`.

## Special files

| File                    | Role                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `src/routes/__root.tsx` | The root route, always rendered: the HTML document (`shellComponent`), `<head>` tags and the app-wide `notFoundComponent`.           |
| `src/router.tsx`        | Exports `getRouter()`, called for every server request and once in the browser. Router-wide options such as preloading and rewrites. |
| `src/start.ts`          | Optional. Global request and server function middleware (`createStart`). Its presence turns off the built-in CSRF check; see below.  |
| `src/routeTree.gen.ts`  | Written by the router plugin from `src/routes/`. Committed, never edited by hand.                                                    |
| `route.tsx`             | The route of a folder, usually a layout: `products/route.tsx` is `/products`.                                                        |
| `index.tsx`             | Matches the folder's URL exactly: `products/index.tsx` is `/products`.                                                               |
| `-` prefix              | A file or folder the router plugin leaves out of the route tree, for code that sits next to routes.                                  |

There is no server or client entry file: Start uses its own defaults until `src/server.ts` or `src/client.tsx` exists.

## Behavior worth knowing

### `_` and `-` mean the opposite of Next.js and Astro

In Next.js and Astro a leading `_` keeps a folder out of routing. Here a leading `_` makes a pathless layout route, a trailing `_` leaves the parent layout, and `-` is the prefix that excludes a file. A `_components/` folder copied from a Next.js app is picked up by the route generator.

### beforeLoad is not a security boundary

`beforeLoad` runs on the server for the first request and in the browser on every client navigation. `/account` uses it as a routing guard (no `?as` gives a 307 to `/login`), but anything it checks can be bypassed in the browser. Check authorization in server functions, server routes or request middleware, which only run on the server.

### Defining `src/start.ts` turns off the built-in CSRF check

Without `src/start.ts`, Start rejects cross-site calls to server functions on its own. Once the file exists, only the middleware it lists runs, so `src/start.ts` adds `createCsrfMiddleware()` for server function requests itself. A cross-site call to the products server function gets a 403.

### Error messages reach the page in production

`/crash` throws in its loader. The production server answers with a 500, and `errorComponent` renders the error's message into the HTML. Show a generic text for unexpected errors rather than the message itself.

### A masked URL needs the same page on the server

A route mask lives only in the browser's history state, so a reload sends `/photo/1` to the server, which renders the full page. With the default settings the browser restores the modal instead, and React reports a hydration mismatch (error 418). `unmaskOnReload: true` on the mask makes the browser render the full page too.

### An input-only rewrite becomes a redirect

The server answers every URL in its public form. An input rewrite without a matching output rewrite, such as `/about-us` to `/about`, gets a 307 to `/about` rather than the About page under the old URL. `/team` keeps its URL because its rewrite works in both directions.

### Prerendered pages are files for a static host

`pnpm build` writes `dist/client/about/index.html`, but the Start server, including `pnpm preview`, still renders `/about` on each request and serves the file only at `/about/index.html`. The files pay off on a static host or CDN in front of the server. Product ids that are not listed, such as `/products/4`, are always rendered on request.

### A splat also matches its folder

`files/$.tsx` matches `/files` with an empty `_splat`, like Astro's `[...path]` and unlike Next.js's required `[...slug]`.

## Type-safe routing

`src/routeTree.gen.ts` registers the route tree and the router with TypeScript, so no route type is written by hand:

- `<Link to>`, `navigate()` and `redirect()` accept only paths that exist, and require their `params` and a valid `search`. That is why `/missing` on the home page is a plain `<a>`.
- `Route.useParams()`, `useSearch()`, `useLoaderData()` and `useRouteContext()` are typed from the route's own `validateSearch`, `loader` and `beforeLoad`.
- `linkOptions()` checks link objects defined outside JSX, such as the list on the home page.

The file is committed, so `pnpm typecheck` works on a fresh checkout without a build.

## Deployment

The app needs a JavaScript server: SSR, server functions, server routes and request middleware all run there. `pnpm build` writes the server bundle to `dist/server`, and the browser assets and prerendered pages to `dist/client`.

```bash
pnpm build
pnpm preview
```

`pnpm preview` runs the production build locally on http://localhost:3001. For a host or runtime, see the official [hosting guide](https://tanstack.com/start/latest/docs/framework/react/guide/hosting).
